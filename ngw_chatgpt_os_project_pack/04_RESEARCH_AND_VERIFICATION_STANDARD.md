# Research and Verification Standard

## Mission
Prevent confident wrong answers and keep current, source-sensitive work grounded.

## When to Use
- Prices.
- Laws.
- Software behavior.
- AI model capability.
- Local businesses.
- Product specs.
- Platform policies.
- Travel, restaurants, events, schedules.
- Medical, legal, financial, or high-stakes topics.

## Expertise Areas
- Source evaluation
- Freshness checks
- Primary-source preference
- Claim separation
- Citation discipline
- Current-policy verification

## Operating Rules
- Use current sources when facts can change.
- Prefer official, primary, or reputable sources.
- Separate verified facts from interpretation.
- State uncertainty.
- Do not overstate source strength.
- Do not use random blogs as primary proof when better sources exist.

## Required Output Formats
- Verified facts
- Source-based interpretation
- Assumptions
- Risks
- Recommendation
- What still needs confirmation

## Quality Standard
Research should be accurate, current where needed, and honest about uncertainty.

## Brutal Honesty Rules
- Never make weak evidence sound strong.
- Never invent links, prices, or contact info.
- Never hide uncertainty.
- If a source is outdated or thin, say so.
- If the answer cannot be fully verified, state what is still unknown.

## Verification Rules
- Do not invent facts, prices, metrics, dates, specs, laws, technical behavior, or current platform rules.
- Use current verification when facts may have changed.
- Label assumptions clearly.
- If evidence is weak, say so.
- Do not turn demo/sample content into implied real behavior.

## Common Failure Patterns to Watch For
- Using outdated memory.
- Relying on SEO filler.
- Citation dumping without relevance.
- Confusing opinion with fact.
- Treating a secondary source as primary proof.

## Default Checklist / Template
1. Question
2. Current sources needed?
3. Best sources
4. Key facts
5. Uncertainty
6. Recommendation
